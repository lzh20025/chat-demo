# 记忆

让新对话一开始就了解用户：用户是谁、之前聊过什么。全部数据保存在浏览器 IndexedDB，对模型服务只要求「system + 一条 user 消息 → 文本」，不依赖任何服务端扩展。

## 两类内容

| 内容                           | 是什么                                               | 更新时机                           | 存储                         |
| ------------------------------ | ---------------------------------------------------- | ---------------------------------- | ---------------------------- |
| 记忆条目（界面：我记得的事）   | 关于用户的一件事，单行，带分类、出处和是否经用户确认 | 回答完成后几秒内；后台定期合并整理 | `memoryItems`，每条一行      |
| 近期对话摘要（最近聊过的话题） | 每个对话一条 1-3 句的备忘                            | 与提取记忆同一次调用               | `memoryDigests`，键为会话 id |

元数据（不再提及、待清理、删除过的内容、上次整理时间）在 `memoryProfile` 的唯一一条记录里。两类内容都预先算好，请求时整段追加到 `system` 末尾（`<memory>` 块），模型不需要检索或调用工具。

摘要生成前的空档由「用户原话节选」填补：回答一完成就把该会话最近 4 条用户消息的节选记在内存里，新会话立刻可用，摘要生成后替换。

## 流程

```text
回答完成 ── noteReplyDone ──► 记下原话节选（立即可用）
                              └─ 4 秒后 / 说了「记住、忘掉」立即 / 离开会话 ─► digestSession
                                   一次调用：备忘 + 记忆操作（ADD / ASK / UPDATE / DELETE）
                                   └─ 校验后在一个事务里写入 ─► 改动挂到这轮提问上，回答下方显示、可撤销
                                        └─ 达到条件 ─► maybeDream：ADD / UPDATE / DELETE / MERGE
发起请求 ── getMemorySnapshot(sessionId) ──► system + <memory> 块，同一个块和编号映射存到回答上
```

### 回答后提取（快路径）

- 只从「新内容」里提取：摘要记录已覆盖到的最后一条消息时间（`coveredAt`），之后创建的用户消息才是新的，也晚于上次清空记忆。编辑提问、切换分支后消息数会变，所以不用消息数判断。没有新的用户消息（续写、重新生成）时只写备忘。
- 模型看到已有条目（编号 `k1…` 只在这次有效）、不要再记录的内容（删除过、拒绝过、待确认、不再提及）和标出新内容的对话，输出一行 `NOTE`、若干行操作、最后一行 `END`。没有 `END` 说明输出被截断或格式不对，备忘照用，操作一条都不用。
- 操作由 `ops.ts` 按规则落库，模型只是提议：
  - 编号对不上、条目在调用期间被改过的操作丢弃；
  - 已有的、删除过的（用户这次明确要求记住时除外）、命中不再提及的不新增；
  - 疑似凭证（长数字串、常见密钥前缀）直接丢弃；
  - 健康、财务、性取向、宗教、政治立场等敏感内容先问：模型用 `ASK`，或代码按关键词把 `ADD` 升级为待确认；用户明确说「记住」时直接保存；
  - 一次最多新增 5 条、修改 3 条、删除 3 条；条目到 80 条时不再自动新增，提示「记忆已满」。
- 用户明确要求记住的条目记为用户确认过（`origin: 'user'`）。快路径可以改、删用户确认过的条目（是用户在对话里亲口说的），每次改动都在对话里告知、可撤销。
- 改动（`MemoryChange[]`）挂在这轮的提问上（`UserMessage.memoryChanges`），显示在它当前可见的回答下方：重新生成、续写都会替换回答，挂在回答上会丢。记忆层不依赖聊天层，由聊天层注册回调写入：会话在内存里直接更新，不在内存里用一个事务读-改-写，对话已被删除就放弃。
- 注入说明里告诉模型：用户要求记住或忘掉时直接答应，系统会在回答后更新。这句跟在身份说明后面而不在记忆块里，记忆为空时也有。

### 后台整理（慢路径）

- 新摘要累计 3 条、距上次整理超过 6 小时且有新摘要、条目到上限且上次整理后有变化，或手动「立即整理」时，把全部已生效条目和新摘要交给模型，输出增、改、删、合并。
- 用户确认过的条目由代码保护：整理不能改写、删除或合并它们，也不能新增敏感内容。合并整条成立或整条不做；一次删光全部自动条目、或条目较多（10 条以上）时删掉超过六成的整批作废（旧版档案里常有大量琐事，条目少时第一次整理删掉多数是正常的）；整理期间用户动过记忆（元数据 `updatedAt` 变了）整批作废，以用户操作为准。

### 一致性

- 每次写入都在一个 IndexedDB 事务里基于最新数据计算（`db.commitMemory`）：条目、元数据、摘要、活动记录一起写入，对话已被删除就放弃。写入后重新读取，并通过 BroadcastChannel 通知其他标签页。
- 模型调用期间清空了记忆（包括在其他标签页，通过共享的清空时间判断）、关闭了记忆或替换了历史，结果丢弃。后台整理用 Web Locks 在标签页间互斥；同一段内容被两个标签页同时整理时，后写入的发现已被覆盖就放弃。
- 数据库升级时其他标签页还开着旧版本，新页面提示关闭它们；旧页面让出连接并提示刷新。

## 注入

- 只注入已生效的条目，按分类分节：`# 用户档案` 下 `## 基本情况` 等小节，每条 `- [mN] 内容`。超过 4000 字时整条取舍，用户确认过的优先。
- 同一会话沿用首次请求时的快照，system 保持稳定；用户改动记忆、回答后提取改写或删除了条目时快照作废，下一轮按新内容注入。
- 当前会话自己的摘要不注入；临时对话什么都不注入。

## 删除、别再提与撤销

- **删除**：条目进入「删除过的内容」，之后自动整理不会原样记回来；用户在对话里明确再说一次，仍然可以记住。
- **别再提这件事**：条目删除，内容进入不再提及的清单，之后的摘要、整理和回答都会带上这份清单（只靠在记忆块里写「不要提及」拦不住，模型仍会从别的对话摘要里把这件事带出来）。设置里可恢复。
- **撤销**（对话内）：撤销新增等同删除；撤销修改恢复原文；撤销「已忘记」把条目放回。条目之后被编辑、整理或合并过时不能直接撤销，只给「管理记忆」入口。
- **不用**（待确认的敏感内容）：删除并记入删除过的内容，之后不再询问。
- 以上都会清理相关对话的摘要：删除、撤销清理条目出处的对话（没有出处时所有对话），别再提清理所有对话。清理完成前这些摘要和对应的原话节选不注入；记忆关闭、没有 API Key 或请求失败时留到下次启动或重新开启再试。

## 临时对话

新对话页可以切到临时对话（`Session.temporary`），创建后不可切换：不注入记忆，回答后不整理，启动补齐也跳过；system 里说明这是临时对话，用户要求记住时如实说明不会保存。对话本身照常保存在历史里，列表里带标记。

## 用户控制

设置 →「记忆」默认只显示开关和「我记得的事」，其余逐级展开：

- 开关：关闭后不注入也不整理，已有记忆保留。
- 要记住这些吗：待确认的敏感内容，确认后才生效。
- 我记得的事：按分类列出，可添加、编辑、删除、别再提；展开一条可看出处（可跳回那次对话）。
- 最近聊过的话题（折叠）：逐条「不再参考」，删除后除非该对话有新消息，否则不再生成。
- 不再提及（折叠，有内容才出现）：可恢复。
- 高级（折叠）：整理状态与立即整理、整理记录、发给模型的原文、清空记忆。

删除某个对话会同时删除它的摘要；删除全部对话会清空摘要，记忆条目保留。

## 可观测性

记忆是否生效、从哪里来，都可以在界面上追溯，不需要抓包：

- **对话内提示**：回答下方一行显示这轮记住、更新、忘记了什么，或询问是否记住敏感内容；第一次出现时附一句说明。
- **自定义指令**不是记忆：用户自己写的要求，存在本机设置里（`services/instructions.ts`），每次请求读取当前内容，注入在身份说明之后、记忆块之前，不参与整理，清空或关闭记忆都不影响。它的归因编号是 `i1`，和记忆编号一起由 `<memory-used>` 报出，来源面板里作为「自定义指令」条目显示。对话中途改了或清空了指令时，system 里会明说「要求变了，之前的做法不要沿用」。
- **归因标记要回传**：标记在保存时从正文剥离，但发给模型的历史回答会按保存的编号把它补回去（`toAssistantParam`），否则几轮之后模型自己也不再输出，归因就断了。
- **每条回答参考了什么**：请求时追加的 `<memory>` 块原文保存在回答的 `memory` 字段，编号到条目 id 的映射保存在 `memoryIds`。回答下方的来源按钮在右侧面板里和搜索到的网页一起列出实际用到的条目：模型在回答末尾用 `<memory-used>m2,m7</memory-used>` 报出用到的编号，这一行流式显示时隐藏、回答结束时从正文剥离并存入 `memoryUsed`（见 `marker.ts`）；归因是模型自报，可能漏报或多报。面板里的条目可更正、别再提、查看出处，按条目 id 操作；较早的回答没有 `memoryIds`，按原文查找。过往对话展示的是用户原话节选（`memoryChats`），只有「不再参考」。
- **整理记录**：每次整理一个对话、后台整理全部记忆都写一条活动记录（`memoryLog`，保留最近 50 条），含触发原因、结果（已保存、已跳过、已作废、失败）、这次对条目的增改删、摘要正文和耗时。

活动记录里有摘要原文，因此清空记忆或删除全部对话时清空全部记录，删除某个对话或某条摘要时删除对应的记录。回答上的 `memory` 快照和提问上的 `memoryChanges` 属于对话本身，随对话保留，删除对话即一并删除；不进入历史导出。

## 迁移

旧版的用户档案是一整篇 Markdown，启动时迁移成条目，只做一次（`migrate.ts`）：按 `##` 小节归类，每行一条，文本取法与旧版按原文找行一致，旧回答的来源面板仍能对上。用户手改过或从没自动整理过的档案整体视为用户确认过的内容。原文保留在元数据里，不删除。

## 导出与导入

记忆随历史 ZIP 导出：写在 `manifest.json` 的扩展字段里（不新增 ZIP 条目，旧版本仍能导入），只含已生效的条目和不再提及的清单；待确认条目、摘要和整理记录不导出。导入是合并：重复的、命中本地不再提及的跳过，条目文本重新清洗，受条数上限约束。格式见[历史导入导出](../chat/history/README.md)。

## 文件

- `prompts.ts`：中英文提示词与分类名。
- `ops.ts`：纯函数——解析模型输出的操作，按规则校验并落到条目上。
- `text.ts`：纯函数——拼对话文本、标出新内容、渲染与解析记忆块。
- `migrate.ts`：旧版档案迁移。
- `state.ts`：共享状态、事务写入（`commit`）、快照、标签页间同步。
- `store.ts`：整理与调度（快路径、后台整理、清理摘要、启动补齐）。
- `items.ts`：用户操作（添加、编辑、删除、别再提、确认、撤销、导入导出）。
- `llm.ts`：唯一的模型调用入口 `complete()`；接入其他服务时只需替换它。

## 已知限制

- 记忆默认只在当前浏览器内；开启云端同步后在设备间按条目合并（见 [云端同步](../sync/README.md)），否则换浏览器需要通过历史导出、导入带过去。
- 每次整理一个对话、后台整理和清理摘要都会额外调用一次模型（默认 `deepseek-flash`）。
- 记什么、敏感与否主要靠提示词和关键词判断，可能漏记、误记或多问；凭证类信息有代码兜底过滤，但不保证识别所有形式。
- 旧版本导入新导出的归档时，会丢掉临时对话的标记，这些对话可能被整理进记忆。
