# 记忆

让新对话一开始就了解用户：之前聊过什么、用户是谁。全部数据保存在浏览器 IndexedDB，对模型服务只要求「system + 一条 user 消息 → 文本」，不依赖任何服务端扩展。

## 两层结构

| 层           | 内容                          | 更新时机                                                             | 存储                         |
| ------------ | ----------------------------- | -------------------------------------------------------------------- | ---------------------------- |
| 近期对话摘要 | 每个会话一条 1-3 句的备忘     | 回答完成 8 秒后；开启新对话、切换会话或切到其他窗口时立即            | `memoryDigests`，键为会话 id |
| 用户档案     | 一份 Markdown，长期稳定的信息 | 累计 3 条新摘要，或有新摘要且距上次整理超过 6 小时；首次有摘要时立即 | `memoryProfile`，只有一条    |

两层都预先算好，请求时整段追加到 `system` 末尾（`<memory>` 块），模型不需要检索或调用工具。

摘要生成前的空档由「用户原话节选」填补：回答一完成就把该会话最近 4 条用户消息的节选记在内存里，新会话立刻可用，摘要生成后替换。

## 流程

```text
回答完成 ── noteReplyDone ──► 记下原话节选（立即可用）
                              └─ 延时 / 离开会话 ─► digestSession ─► 保存摘要
                                                       └─ 达到条件 ─► maybeDream ─► 整体重写档案
发起请求 ── getMemoryBlock(sessionId) ──► system + <memory> 块，同一个块存到回答的 memory 字段
```

- 同一会话沿用首次请求时的记忆块快照，system 保持稳定；用户在设置里改动记忆后快照作废，下一轮即按新内容注入。
- 当前会话自己的摘要不注入。
- 档案是整体重写而不是追加：模型会合并重复、删除被推翻的内容、把过期的计划改写为已发生的事。
- 用户手动编辑过的档案在下次整理时作为「用户确认过的事实」交给模型。
- 整理期间用户编辑或清空了记忆时，本次整理结果作废，以用户操作为准。
- 多个标签页通过 BroadcastChannel 同步，档案整理用 Web Locks 互斥。

## 用户控制

设置 →「记忆」里可以看到模型能看到的全部记忆：

- 开关：关闭后不注入也不生成，已有记忆保留。
- 档案：查看、编辑、立即整理。
- 近期对话：逐条删除。删除后除非该对话有新消息，否则不再生成。
- 清空：删除档案和全部摘要；此前的对话不会再被自动整理进记忆。

删除某个对话会同时删除它的摘要；导入或删除全部对话会清空摘要，档案保留。

## 可观测性

记忆是否生效、从哪里来，都可以在界面上追溯，不需要抓包：

- **自定义指令**不是记忆：用户自己写的要求，存在本机设置里（`services/instructions.ts`），每次请求读取当前内容，注入在身份说明之后、记忆块之前，不参与整理，清空或关闭记忆都不影响。它的归因编号是 `i1`，和记忆编号一起由 `<memory-used>` 报出，来源面板里作为「自定义指令」条目显示。对话中途改了或清空了指令时，system 里会明说「要求变了，之前的做法不要沿用」，否则模型会照着历史回答的样子继续写。
- **归因标记要回传**：标记在保存时从正文剥离，但发给模型的历史回答会按保存的编号把它补回去（`toAssistantParam`）。否则模型看到历史回答都不带标记，几轮之后自己也不再输出，归因就断了。
- **调优**：来源面板里每条记忆有操作菜单。档案条目可更正（改档案里那一行）、「别再提这件事」（从档案删除并记入 `MemoryProfile.muted`，之后的摘要、整理档案和回答都会带上这份清单，已有摘要里的相关内容由一次模型调用在后台删掉（清理完成前旧摘要不注入，记忆关闭、没有 API Key 或失败时留到下次启动或重新开启再试；清单不为空时也不注入未经摘要的用户原话节选），设置里可恢复；只靠在记忆块里写「不要提及」拦不住，实测模型仍会从别的对话摘要里把这件事带出来）、查看来源（从活动记录反查最早写出这一行的那次整理）；过往对话只有「不再参考」（删除摘要）。没有相关/不相关投票：记忆整段注入、没有排序，这类信号没有消费者。
- **每条回答参考了什么**：请求时追加的 `<memory>` 块原文保存在回答的 `memory` 字段（`AssistantMessage.memory`）。回答下方显示「参考了记忆」，点开在右侧「来源」面板里和搜索到的网页一起列出。记忆整段注入，但面板只列实际用到的条目：记忆块里每条有编号（`[m1]`…），模型在回答末尾用 `<memory-used>m2,m7</memory-used>` 报出用到的编号，这一行流式显示时隐藏、回答结束时从正文剥离并存入 `memoryUsed`（见 `marker.ts`）；归因是模型自报，可能漏报或多报。其中过往对话展示的是用户原话节选（随回答保存在 `memoryChats`，摘要记录里对应 `excerpt`），不是模型看到的摘要。记忆关闭或为空时不显示。这里展示的是模型看到的内容，不代表每一条都被用到。
- **记忆是怎么来的**：每次生成摘要、整理档案都写一条活动记录（IndexedDB `memoryLog`，保留最近 50 条），在设置 →「记忆」→「活动记录」中查看：
  - 类型与对象：摘要（对应哪个对话）或档案；
  - 触发原因：回答后自动、离开对话、启动时补齐、立即整理；档案另有首次生成、新摘要累计 3 条、距上次超过 6 小时；
  - 结果：已保存、已跳过（模型输出 `SKIP`）、已作废（整理期间用户编辑了档案，或模型输出为空）、失败（附错误信息）；
  - 产出：摘要正文、整理后的档案全文，以及这次整理并入了哪些对话的摘要；
  - 耗时。

活动记录里有摘要和档案的原文，因此清空记忆、导入或删除全部对话时清空全部记录，删除某个对话或某条摘要时删除对应的摘要记录。期间被清空或替换而丢弃的整理不留记录。回答上的 `memory` 快照属于对话本身，随对话保留，删除对话即一并删除；不进入历史导出。

## 文件

- `prompts.ts`：中英文提示词。
- `text.ts`：纯函数——拼对话文本、渲染记忆块、解析模型输出。
- `llm.ts`：唯一的模型调用入口 `complete()`；接入其他服务时只需替换它。
- `store.ts`：状态与调度。

## 已知限制

- 记忆只在当前浏览器内，不跨设备，也不包含在历史导出里。
- 每次摘要和整理都会额外调用一次模型（默认 `deepseek-flash`）。
- 档案允许模型做有依据的归纳，可能出错；敏感信息只在用户明确说过时记录，凭证类信息不记录。这些规则靠提示词约束，不是硬性过滤。
